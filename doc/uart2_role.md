# UART2 用途选择：VOFA / VT13 接收

> 后续更新：VT13 默认已接管本车云台、底盘与发射。操控、接口、回退和最新验证以 [VT13 整车操控与接口](vt13_control.md) 为准。下面的“仅接收”范围是 2026-11-19 阶段的历史边界。

2026-11-19；适用 `StandardRobotpp master@19ad0dc` 本机未提交工作区。已完成主机检查和 Keil 编译链接，未烧录、未验证实际接线及收帧。

## 选择方式

C 板丝印 **UART2** 对应 STM32 **USART1**，TX 为 PA9、RX 为 PB7。只修改 `application/robot_param.h` 中这一行，重新编译并烧录后生效：

```c
#define UART2_ROLE UART2_ROLE_VT13
```

| 宏值 | 串口配置 | 工作内容 |
| --- | --- | --- |
| `UART2_ROLE_VT13`，当前默认 | 921600、8N1、仅接收，循环 DMA | 校验、提供快照，默认作为整车控制源 |
| `UART2_ROLE_VOFA` | 115200、8N1、仅发送 | 原有 VOFA 波形发送及观测 |
| `UART2_ROLE_LEGACY` | 原板间通信配置 | 保留原工程的板间协议兼容路径 |

`VOFA_ENABLE`、`VT13_ENABLE` 由用途宏派生，不需要分别修改。非法用途、矛盾的 VOFA 配置，以及独占模式下的旧板间控制/自定义控制器串口占用，会产生编译错误。原 `VOFA_ENABLE=0` 不再作为单独的模式选择开关。

## 2026-11-19 仅接收阶段的控制边界（历史）

按用户确认，**VT13 本次仅接收和校验，不接管车辆**。`__RC_TYPE` 保持 `RC_DT7`，原 USART3 遥控器、DBUS 检测、底盘/云台/发射逻辑保持。接收到的 VT13 帧不会写入 `rc_ctrl`，也不会刷新 DT7 在线状态；DT7 断线仍按原有逻辑处理。此阶段禁止将 `__RC_TYPE` 直接改成已有的 `VT13` 占位类型。

后续解耦模块应使用 `Vt13ReadInput()` 读取输入快照，再明确设计单个 C/N/S 开关、暂停键、自定义键与车辆模式的映射。不要将它直接套为 DT7 的两个拨杆。

## 接线与输入接口

- VT03 **TX → UART2 RX（PB7）**，两端 **GND 相连**；本次只接收，不要求 C 板 TX 回传。
- 电源管理模块原裁判串口继续使用 USART6。不得将其 TX 或 USB 转串口模块的 TX 与 VT03 TX 并接到同一个 RX。
- VT03 的供电、对频、VT13 与电脑/客户端连接仍按设备手册进行；这里的编译通过不代表上述硬件连接已验证。

输入 API 位于 `application/remote_control/vt13/vt13_remote.h`：

```c
Vt13Input input;
Vt13ReadInput(&input);
if (input.valid) {
    /* 此处由后续独立控制模块消费输入。 */
}
```

- `channel[0..3]` 在当前配置下依次为右横、右竖、左竖、左横。根据实物反馈，本车图传的左摇杆两轴与手册相反。`robot_param.h` 中的 `VT13_SWAP_LEFT_STICK_AXES=1` 会交换 `channel[2]` 和 `channel[3]`，设为 `0` 恢复帧内原始顺序。数值为 364..1684、中值 1024，`wheel` 同范围。
- `normalized[0..3]` 与 `channel` 的轴顺序一致，使用 `(channel - 1024) / 660.0` 归一化。364、1024、1684 分别对应 -1.0、0.0、+1.0。`Vt13ReadInput()` 返回无效快照时四轴归零。Keil 中可展开 `vt13_parser.input.normalized` 查看最近发布的浮点值，用有效帧计数确认刷新。
- `mode_switch`：C=0、N=1、S=2；另提供暂停、自定义左右键、扳机、鼠标 XYZ/三键、键盘位图。
- `sequence` 仅在整帧 CRC 和字段均有效时增加。`update_time_ms` 为最后有效帧的软件接收时刻，不是发端采样时刻。
- 100 ms 未收到有效帧时，API 返回 `valid=false`，通道/拨轮回中、鼠标与按键清零；保留序号和最后有效时间用于诊断。坏帧不刷新有效时间，支持 tick 回卷。
- `Vt13ReadStats()` 提供字节数、有效帧数、CRC 错误和字段错误计数。`vt13_uart_stats` 提供 UART 错误、启动失败和恢复统计。`dma_stalls` 记录未收到错误回调但检测到 DMA 已停止的次数。`running` 表示驱动最近一次检查确认接收 DMA 已启用，判断链路在线请看有效帧是否持续到达。
- 静态解析器内部的上一帧不是带超时的业务输入，请通过 API 读取，不直接用调试器看到的旧字段作为在线依据。

## 帧校验与串口恢复

接收 21 字节 `A9 53` 帧，支持逐字节、跨缓冲、粘包、噪声及错帧重新找头。通道/拨轮范围、C/N/S 值和鼠标按键状态均经过校验；长断流前后的残片不会拼成新帧。

**官方资料有 CRC 冲突：**用户提供的 PDF 写 CCITT-FALSE；[官网校验示例](https://rm-static.djicdn.com/tem/17348/Example_Code_for_Data_Frame_and_Validation.c)实际使用反射多项式 `0x8408`、初值 `0xffff`、无最终异或、帧尾低字节在前。本实现严格跟随该官方可执行示例，不静默接受两种算法。已与原示例交叉测试；实际设备固件版本与线上帧仍待核验。若实机 CRC 错误持续增加，应保存原始帧和版本核对，不能直接取消校验。

USART1 和 DMA2_Stream5 均为抢占优先级 5。循环 DMA 持续接收，空闲中断处理短帧，半满/全满回调处理连续流及回卷，不在每次空闲时重启 DMA。串口/DMA 错误立即使输入无效，通信任务按 100 ms 重试间隔执行恢复；接收恢复后需新有效帧才能再次得到有效输入。

通信任务也会检查 USART1 的 `DMAR` 位和 DMA 通道的使能位。任一位掉了，驱动撤销旧快照，重新初始化 RX DMA 并启动接收。正常空闲或图传断线时，只要这两个使能位仍在，就不会反复重启 DMA。

VT13 模式禁用旧板间发送、自定义控制器 PC 发送和 VOFA 发送，旧 BSP 入口不能重新配置其 DMA。VOFA 模式继续使用原有发送及故障恢复。DMA 缓冲的链接位置和运行时地址均检查为 SRAM，最终 VT13 map 地址为 `0x2000092c`，未放入 CCM。
