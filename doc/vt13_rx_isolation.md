# VT13 有效帧间歇超时：第 2 项接收隔离（2026-11-24）

适用 `StandardRobotpp master@ec77f6b` 当前工作区。第1项失联停机锁定保持 `GIMBAL_INIT_TEST_INPUT_LOSS_LATCH=1`，本轮两个对照配置只改变 `VT13_TEST_RX_POLL`，其他控制、参数、接收有效性和恢复策略不变。

## 已有证据及未确定部分

用户失效后回C的首条记录：READY/IMU下输入无效，帧龄100 ms，source=1、序号888；回C后锁定位为0是有效C解锁的预期结果。UART累计最大帧龄310 ms、进入采样超时88次，UART错误/恢复/DMA停止均0；这是整段运行累计值，不是仅一次N档失效次数。

随后两张解析计数截图显示有效帧9778→9900，CRC错误和非法字段一直为0，首张205338字节正好是9778帧×21字节。第二张字节和帧数差一帧，Watch逐项异步更新，不能由此认定损坏。当前不支持已交给解析器的数据持续被CRC或字段检查拒绝；仍不能区分图传/线端断流、DMA生产或接收中断消费延迟。

## 只改变接收事件补触发

```c
// application/robot_param.h
#define VT13_TEST_RX_POLL 1
```

- `1`：当前试验。原通信任务检查DMA生产位置；有未消费数据且接收正常时，仅补挂 `USART1_IRQn`。解析仍在原接收ISR执行，与原DMA回调同优先级串行，不在任务中发布输入，避免被云台读取打断而产生半份快照。
- `0`：原事件对照。仅靠UART IDLE及DMA半满/全满回调取数。

不修改速率、CRC/字段检查、100 ms门槛或时间戳规则，不重启正常DMA，不放行失效输入。无IDLE标志的软件中断不会读DR清IDLE，避免误取新字节。UART错误仍先走HAL停接收及原恢复流程。任务仅在短临界区检查位置、挂请求，不在该临界区解析。

补中断无法恢复尚未到达DMA的数据，也不保证修复硬件断流、长时间屏蔽中断、DMA覆盖或任务饥饿。试验不再超时只支持接收消费时序相关，仍需对照，不能直接认定真实丢中断已定位。

## C 档观察

先保持C档、不让电机动作，程序持续Run。烧录后展开 `vt13_uart_stats`，确认 `rx_poll_enabled=1`；观察20～30秒后截图整个结构，包含parser和新增字段：

| 字段 | 含义 |
|---|---|
| rx_poll_enabled | 1为本轮补中断试验，0为原路径 |
| poll_requests | DMA有未消费数据时补挂接收中断的次数 |
| poll_bytes | 带补挂请求的ISR取走的字节；可能与真实IDLE同时发生，不等同原来必丢的字节 |
| timeout_events / max_input_age_ms | 继续观察是否进入100 ms超时、最大采样帧龄是否达到此前310 ms |
| parser.bytes / valid_frames / crc_errors / invalid_frames | 原解析计数，继续检查坏帧或不发布输入 |

第1项锁定策略固定，先不恢复自动初始化、不同时改其他条件。若超时仍增加，不靠延长门槛或删除零输出让机器人继续运行；后续结合DMA/中断与线端数据定位。对照原路径时只将 `VT13_TEST_RX_POLL` 设为0重新编译，不改变第1项。

## 验证与边界

41项VT13回归通过。新增完整实际UART驱动+实际解析器开关0/1对照，仅替换主机没有的SRAM硬件地址输入及硬件接口，覆盖缺少接收事件时0版超时、1版补中断取数，40帧循环、回卷/拆帧/重复回调、DMA回调先取数、软件请求与真实IDLE同时发生、不在任务解析、不在无IDLE时读DR、CRC拒绝、UART错误停机/恢复和DMA停止。主动漏发接收事件是构造场景，不是实车复现。

同一当前源文件集的原EIDE+ARMCC全量构建补中断1/原路径0两配置，各0错误、14条既有警告；两者失联锁定均为1。证据 `MDK-ARM/vt13-control-verification/rx-poll-isolation-20261124/`。本轮未由Codex烧录、未实车验证、未提交/推送；上位机和既有键鼠/功率/中值现场保持。

## 用户本轮 C 档结果

用户新截图：`rx_poll_enabled=1`，诊断时间48855 ms；超时次数0、最大采样帧龄18 ms，UART错误/恢复/DMA停止、CRC/字段错误均0，补挂404次、带请求ISR处理4539字节，当前C档有效。说明本轮约49秒C档接收正常且新路径确实执行，原图与人工读数存 `poll-on-c-watch.png` / `poll-on-c-observations.json`。

该会话不同于此前310 ms/88次超时记录；此前不加补挂时也曾有C档零超时记录。因此不能仅由当前结果认定真实漏中断是唯一根因，4539字节也可能包含自然IDLE前的正常部分帧，不代表全部原本会丢失。N/S动作工况仍未在这张图中验证。
