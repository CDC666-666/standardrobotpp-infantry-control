# 云台反复初始化：逐项隔离（2026-11-24）

适用 `StandardRobotpp master@ec77f6b` 当前工作区，默认 VT13 控制源。保留原有功率接入、键鼠修改、yaw 中值 `1.63099861f`、鼠标分母 `10000` 及其他现场差异。以下是代码路径和主机验证，不是已定位实车根因。

后续第1项已抓到READY/IMU下帧龄100 ms输入失效，UART累计最大帧龄310 ms、超时88次；约9800帧仍无CRC或字段错误。当前保持第1项失联锁定，下一轮只对照 [第2项接收事件补触发](vt13_rx_isolation.md)，先在C档观察，不同时改变两个开关。

再后续接收补触发开启后，用户仍在N档一直回中、底盘未放行，约3～4秒失能；截图invalid_count=0、接收超时0、最大帧龄22 ms，人工回C前已经FAILED。这次不能继续按输入超时归因，需读取下面新增的首次FAILED记录。

## 哪些情况会进入初始化

| 条件 | 当前 VT13 路径的结果 |
|---|---|
| 云台任务启动，或主控复位后重新运行 `GimbalInit()` | 初始化状态为 DISABLED；首次收到有效 N/S 后进入 RUNNING/INIT |
| 有效 C 档后切入 N/S | C 档清除初始化结果，下一次使能重新回中 |
| 输入失效后恢复 N/S（原行为） | 失效时清除结果并立即停止；恢复后自动重新初始化，这是第 1 项隔离对象 |
| 输入连续无有效帧达到 100 ms | 读取快照失效；走上一项。CRC/字段坏帧不会立刻撤销上一有效帧，但持续无新有效帧可达到超时 |
| UART 错误、DMA 停止或恢复流程使解析器失效 | 同样走输入失效入口；可在达到 100 ms 之前发生 |
| 初始化超过 3000 ms 未实际回中 | 锁定 FAILED、零输出；自身不会返回 INIT |
| READY 后电机/IMU/有限值反馈失效 | 锁定 FAILED、零输出；自身不会返回 INIT |
| 视觉目标/右键变化、USB 状态、鼠标移动或底盘许可变化 | 不是当前路径直接重新进入 INIT 的条件；不能通过注释它们来替代检查初始化状态 |

`GimbalInit()` 在正常云台任务中只调用一次。原初始化撤销有两个实际入口：选模前 `GimbalUpdateInitState()`，以及发送前的最新输入复核。只注释其中一处，另一处仍会清除结果，不能形成可靠对照。

## 本轮只隔离第 1 项：输入失效恢复后的自动重试

为避免手工注释失联保护或漏改一个入口，用一个编译开关切换同一行为：

```c
// application/robot_param_omni_infantry.h
#define GIMBAL_INIT_TEST_INPUT_LOSS_LATCH 1
```

- `1`：本轮试验。初始化已经开始后，输入失效立即零输出并锁定 FAILED；即使有效 N/S 恢复，也保持无力，只有收到**有效 C 档**才解除锁定，然后 C→N/S 重新初始化。
- `0`：原行为对照。输入失效立即停机并清除初始化；有效 N/S 恢复后自动回中。

没有收到首帧的启动阶段不锁定首次初始化。无效快照被清零后的 `mode=0` 不会被当作有效 C 档解除锁定。原 C 档零输出、电机/IMU/数值反馈检查、初始化超时、发射和底盘许可、PID/参数全部保留。公共 `Vt13UpdateInit()` 纯状态机不改；两个实际失能入口统一执行隔离策略。

## 实车观察方式

先断电移除全部控制断点，固定底盘并为云台留出运动空间；保持连续 Run，不在带动力状态暂停或单步。每轮只改变上面这一项，使用同样的输入、供电和负载条件，不累计注释其他保护。

本轮默认已经设为 `1`。编译烧录后，Watch 添加并展开：

```text
gimbal_init_debug
vt13_uart_stats
```

`gimbal_init_debug.test_input_loss_latch=1` 表示烧录的是第 1 项隔离配置；`input_loss_latched=1` 表示确实因输入失效而锁定。异常发生后切回 C 档、待机构停止，再查看首次记录；有效 C 会把当前锁定位清零，但不会覆盖首次 `input_valid/input_age_ms/source/previous_init` 详情。需要重新采集首条记录时从 C 档重新上电。

| 结果 | 可得结论及限制 |
|---|---|
| 原循环变为一次停机，N/S 恢复后仍无力；返回 C 前锁定位为 1 | 输入失效恢复链路能驱动此前循环；尚不能证明 UART/无线/供电/调度中哪一项造成输入失效 |
| 仍反复初始化，锁定位没有置 1，首次记录 `input_valid=1,input_mode=0` | 优先查有效 C 档来源；本轮没有取消有效 C→N/S 的正常初始化 |
| 不锁定也不再复现 | 单次未复现不能排除时序变化或偶发故障，不能直接宣布根因已找到 |
| 模式和记录与隔离开关不一致 | 先核对完整烧录版本、主控复位、有效 C 是否反复出现及内存写入；不能立即继续注释其他项 |

输入丢失后的锁定无力是本轮预期，不是已恢复正常使用；重新操作有效 C→N/S 才能重试。不要为让试验版“继续动”而注释零输出、反馈或失联检查。

## 本机验证与回退

第一轮仅做第 1 项，不同时改反馈、初始化时限、遥控时限或视觉条件。回退只将该开关设为 `0` 后重新编译烧录；不会回退用户其他现场改动。独立构建和输入散列存于 `MDK-ARM/vt13-control-verification/init-isolation-20261124/`；本机测试不等同实车验证，尚未提交、推送或由 Codex 烧录。

原 EIDE/ARMCC 对同一当前源文件集全量构建隔离开关 `1` / 原行为 `0` 两种配置，均 0 错误、14 条既有警告，最终 304 个构建输入散列一致。fromelf 确认试验版锁定状态和 68 字节全局 `gimbal_init_debug` 已保留。全工作区空白检查仍报告原有启动汇编及云台旧行的两处尾随空白，均保留；本轮新增行检查通过。

## 首次 FAILED 原因，不再把回 C 操作当作故障原因

原 `gimbal_init_debug` 只在初始化被输入撤销时记录，因此人工回C可能只留下previous_init=FAILED，无法知道更早为什么失败。新增独立全局 `gimbal_init_failure`，在第一次进入FAILED时锁存，直到重新上电保留，回C不会清除或覆盖。现有两个试验开关及所有超时、反馈、回中判据不变。

重新编译烧录，从C档启动，保持连续Run。若固定机构、留足云台空间后进行一次原有N档检查，失能即回C，待停止后只需截图整个 `gimbal_init_failure`。不要通过延长3000 ms、直接放行底盘或注释反馈来替代原因检查。

| 字段 | 含义 |
|---|---|
| captured | 1表示首次FAILED记录完整，0表示尚无失败记录 |
| reason | 1=初始化超时，2=READY后反馈失效，3=输入失效锁定 |
| previous_init / previous_mode | 失败前状态和模式，1/RUNNING对应初始化中，2/READY对应已完成；云台INIT=2、IMU=1 |
| elapsed_ms / timeout_ms | 距本次初始化启动的毫秒数 / 编译时初始化限时，当前3000；不是反馈异常的持续时间 |
| yaw_error_rad / pitch_error_rad | 失败时的折返关节角误差，正常完成要求两轴绝对值都严格小于0.03 rad，且反馈有效 |
| feedback_mask | 0表示记录瞬间反馈检查均正常，非0按下面位定义识别 |
| yaw_motor_pos / pitch_motor_pos / yaw_mid / pitch_mid | 两轴失败时原始反馈和当前编译中值；本轮中值保持1.63099861f/-2.99279666f，不代表已确认机械正确 |
| input_valid / input_mode / input_sequence / input_age_ms | 失败点所使用的真实输入快照及帧龄 |

反馈故障位可同时置位：bit0=yaw离线（0x1），bit1=pitch离线（0x2），bit2=陀螺仪检测错误（0x4），bit3=加速度计检测错误（0x8）；bit4/5=两电机位置非有限，bit6/7=IMU yaw/pitch位置非有限，bit8/9=IMU yaw/pitch速度非有限，bit10/11=两轴关节角非有限。

reason=1时，先结合feedback_mask和两轴误差区分未到位与反馈无效；若误差也在阈值内，可能刚到截止时才到位或此前反馈未满足，源码在截止时优先判超时，不能据此宣称无需初始化。reason=2才按具体反馈故障位继续隔离。reason=3仍优先查接收链路。3～4秒与3000 ms接近且用户始终未获底盘许可，支持超时候选，尚不替代这条原因记录。
