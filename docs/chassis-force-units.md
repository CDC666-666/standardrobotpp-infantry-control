# 全向轮力控：第一步单位迁移

本次以磁盘上已启用的力控为基线，不恢复轮速 PID、不改轮号/云台坐标变换、不启用功率控制、不加摩擦前馈。目标是明确单位并保持正常未限流时的旧输出，不是改善或证明实车控制效果。

## 参数依据与单位

- 用户确认 M3508，转子到轮子的行星减速比为 `268/17`，半径 `0.08 m`。
- 本地 `Motor-modeling-and-power-control/model_fit/power_model.m` 第 1 行及《开源报告》第 4 页采用 `Kt_rotor = 0.3 / (3591/187)`。
- 沿用该简化模型：`Kt_wheel = Kt_rotor * (268/17) = 0.24628237 N*m/A`。这是模型初值，不是实测标定；没有另行辨识当前减速箱损耗。
- `force_x/y`、`wheel_force[]` 是期望力 N；`torque_wz` 是期望力矩 N*m，不是真实力传感器读数。
- `feedback[]` 和 `set[]` 继续使用电机转子 rad/s，不改变原有轮号和极性约定。
- `current_force_a = wheel_force * WHEEL_RADIUS / CHASSIS_WHEEL_KT`。
- 速度差补偿增益使用 A/(电机 rad/s)，初值为 `20/16384`，等价于原来的 1 raw/(电机 rad/s)。不是参考舵轮的轮端速度增益。
- 两项在 A 层相加后乘 `16384/20`；`wheel[i].set.curr` 和 VOFA `output_command` 仍是原始 CAN 指令。

## 为什么修改 PID 数值

原电流公式：`80 * old_wheel_force * 0.08 + motor_speed_error`。
只把 80 换成物理换算会让力矩项放大约 41.58 倍。
本次按 `scale = 80 * Kt_wheel / 819.2 = 0.0240510129490393` 同步缩放外环增益及积分/输出限幅，利用四轮分配的线性关系保留原输出。

| 参数 | 原值（经验单位） | 迁移值 |
| --- | ---: | ---: |
| 平动 Kp | 100 | 2.4051013 N/(m/s) |
| 旋转 Kp | 100 | 2.4051013 (N*m)/(rad/s) |
| 平动输出/积分上限 | 16000 / 1000 | 384.8162 / 24.051013 N |
| 旋转输出/积分上限 | 16000 / 1000 | 384.8162 / 24.051013 N*m |

I、D 仍为 0；未来使用时遵循当前 `PID_calc` 的逐周期累加/差分定义，而不是连续时间参数。
平动和旋转使用独立宏，初值相同不代表物理调参目标相同。
迁移数值是固定初值，不与 Kt 宏自动联动，否则以后校准 Kt 会被 PID 自动反向抵消。
等效基线是已修正的 `/ (4*L)` 分配，不是更早的 `*L` 错误公式。

## 输出边界

- LOCK 中清目标、清 PID、清电流，保留真实速度观测；Console 在 LOCK 跳过计算。
- 发送前对 DBUS 失联、任一驱动轮离线、任一非有限电流以及无效模式统一发送四个零电流，并清 PID。
- 最终电流边界为 `16000/819.2 = 19.53125 A`，沿用工程原有 16000 指令边界。不是首次带电测试推荐值，也不是电机全工况安全连续电流。
- 失能是零转矩电流，不是主动刹车。条件恢复后自动重新允许输出，没有故障锁存。
- 功率模块周期调用与初始化继续保持停用。以后重新启用时仍须保留最终输出保护，并另行检查功率模型系数。

## 验证方法

`python tests/chassis_force/run.py`：在临时目录编译实际源码中提取的初始化、观测、参考、力控、发送函数和 PID 函数，硬件接口使用桩。对比正常/反向/混合/外环饱和工况的旧电流公式，测试失能、异常值、离线和最终限幅。

`tests/vofa/build_armcc.ps1`：按现有 Keil 工程列表做完整 AC5 编译链接，产物位于临时目录，不烧录。

本次验证结果：

- 20004 组新旧公式对比通过，新增限幅前最大差值为 0.0625 个 CAN 原始指令单位（浮点运算误差）。
- LOCK/恢复、离线、DBUS 失联、NaN/Inf、无效模式和最终限幅测试通过。
- ARMCC 全工程 165 个源文件编译链接通过；底盘源文件单独编译无诊断输出。
- 原有 VOFA 回归测试通过，含 VOFA 开/关两种配置的相关源文件 ARMCC 编译。
- 未烧录、未实车测试；不能据此认定力/电流已标定或实车调参已完成。

下一步先设置合适的低电流测试上限，用实车低速数据验证符号、跟踪误差、电流/温度，再单独调整平动与旋转增益。力控原有偏航和响应问题不因单位迁移而自动解决。
